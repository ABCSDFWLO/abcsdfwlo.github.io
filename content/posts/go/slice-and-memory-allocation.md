Go의 메모리 모델과 핵심 내장 자료구조인 슬라이스(Slice), 그리고 `make`, `new`, 0바이트 구조체(`struct{}{}`)의 동작 원리를 정리한다.

---

## 1. 슬라이스의 내부 구조

슬라이스는 배열 그 자체가 아니라, 런타임 상에서 **배열의 특정 영역을 가리키는 3개 필드의 구조체(SliceHeader)**다.

```go
type SliceHeader struct {
    Data uintptr // 기본 배열을 가리키는 포인터
    Len  int     // 현재 원소 개수 (길이)
    Cap  int     // 원본 배열에서 수용 가능한 최대 용량
}
```

### nil 슬라이스 vs 빈 슬라이스
```go
var a []int            // nil 슬라이스: Data = nil, Len = 0, Cap = 0
b := []int{}           // 빈 슬라이스: Data는 빈 배열 주소, Len = 0, Cap = 0
c := make([]int, 0, 5) // 용량이 확보된 빈 슬라이스: Len = 0, Cap = 5
```

- `nil` 슬라이스라 하더라도 Go의 내장 함수 `append`에 넘기면 자동으로 런타임이 새 배열을 할당하여 정상 동작한다.
- 그러나 `a[0]`처럼 아직 길이가 0인 슬라이스의 인덱스에 직접 접근하면 **`index out of range` 패닉(panic)**이 발생한다.

---

## 2. `make` vs `new`

두 함수 모두 메모리를 할당하지만, 목적과 반환 형태가 완전히 다르다.

| 구분 | `make` | `new` |
| :--- | :--- | :--- |
| **적용 가능 타입** | `slice`, `map`, `chan` (3종류 한정) | 모든 타입 (`int`, `struct`, 배열 등) |
| **동작 방식** | 내부 자료구조를 초기화하고 사용 가능한 상태로 만듦 | 메모리를 0(Zero Value)으로 초기화만 함 |
| **반환값** | 초기화된 **값(T)** 그 자체 | 할당된 메모리의 **포인터(*T)** |

```go
// make: 슬라이스 내부 헤더와 기본 배열을 만들고 슬라이스 값 자체를 반환
s := make([]int, 5, 10) // []int 반환

// new: 포인터만 반환하므로 슬라이스나 맵의 내부 런타임 구조가 비어 있음
p := new([]int)         // *[]int 반환 (*p는 nil 슬라이스 상태)
```

## 3. 0바이트 빈 구조체: `struct{}`와 `struct{}{}`

- **`struct{}`**: 필드가 하나도 없는 구조체 **타입**.
- **`struct{}{}`**: 그 빈 구조체 타입의 **인스턴스(값)**.

빈 구조체는 실제로 메모리를 **0바이트(0 bytes)** 차지한다. 아무리 많은 인스턴스를 만들어도 메모리를 소모하지 않으므로 Go에서는 다음과 같은 패턴에 적극 활용한다.

### 1) Set(집합) 자료구조 구현
Go에는 표준 `Set` 타입이 없다. `map[string]bool`을 쓰면 불리언 값(1바이트)이 낭비되지만, `map[string]struct{}`를 쓰면 순수하게 Key만 존재하는 완벽한 $O(1)$ Set이 된다.

```go
set := make(map[string]struct{})

// 요소 추가
set["apple"] = struct{}{}
set["banana"] = struct{}{}

// 요소 존재 여부 확인
if _, exists := set["apple"]; exists {
    println("apple이 존재합니다.")
}
```

### 2) 동기화 시그널 전송 채널
데이터 전달 목적이 아니라 순수하게 "작업 완료"나 "신호 발생"만을 알리는 채널로 사용한다.

```go
done := make(chan struct{})

go func() {
    // 작업 수행...
    done <- struct{}{} // 0바이트 시그널 전송 (또는 close(done))
}()

<-done // 완료 대기
```
