Go 애플리케이션이 구동될 때 패키지 변수, `init()`, 그리고 `main()`이 어떤 순서로 평가되고 실행되는지 정리한다.

---

## 1. 초기화 및 실행 흐름

Go 런타임의 프로그램 초기화 과정은 다음과 같은 명확한 순서를 따른다.

```
[1. 의존 패키지 초기화]
       ↓
[2. 패키지 레벨 변수 초기화]
       ↓
[3. init() 함수 실행]
       ↓
[4. main() 함수 실행]
```

### 상세 단계

1. **의존 패키지 탐색 및 초기화**:
   - `main` 패키지가 import하는 패키지들을 DFS(깊이 우선) 방식으로 재귀 탐색한다.
   - 의존성 그래프의 가장 깊은 곳(리프 패키지)부터 초기화가 완료되어야 상위 패키지의 초기화가 시작된다.

2. **패키지 레벨 변수 초기화 (Package Variable Initialization)**:
   - 전역/패키지 스코프에 선언된 `var` 변수들이 초기화 식에 따라 평가된다.
   - 변수 간 상호 의존 관계가 있다면 의존성에 맞게 순서가 자동으로 조정된다.

3. **`init()` 함수 실행**:
   - 패키지 변수 초기화가 끝난 후, 패키지 내에 정의된 `init()` 함수가 순차적으로 실행된다.
   - 한 패키지나 소스 파일 안에 `init()` 함수가 여러 개 존재할 수 있으며, 이 경우 소스 코드에 선언된 순서대로 호출된다.

4. **`main.main()` 진입**:
   - 모든 패키지와 변수, `init()` 함수의 실행이 완료된 후에야 최종 진입점인 `main()` 함수가 실행된다.

---

## 2. 주의점: 패키지 레벨 선언과 `:=` 연산자

패키지 스코프(함수 외부)에서는 `:=` (Short Variable Declaration) 연산자를 사용할 수 없다.

```go
package main

// 컴파일 에러: syntax error: non-declaration statement outside function body
// count := 10 

// 정상: var 키워드를 명시해야 한다.
var count = 10
```

`:=` 연산자는 함수 내부 블록 스코프에서만 허용되는 문법 설탕(Syntactic Sugar)이기 때문이다.

---

## 3. `init()` 함수의 특징

- 인자를 받을 수 없고, 반환값도 가질 수 없다 (`func init()`).
- 코드 내에서 명시적으로 직접 호출할 수 없으며 오직 Go 런타임에 의해서만 1회 실행된다.
- **부수 효과 임포트(Blank Identifier Import)**:
  패키지의 함수를 직접 호출하지 않고 순수하게 해당 패키지의 `init()` 함수 실행만을 목적으로 import할 때 `_`를 사용한다.
  ```go
  import (
      _ "image/png" // PNG 디코더를 image 포맷 테이블에 등록하는 init() 호출
  )
  ```
